检查机场服务的设备兼容性时，要同时核对服务商当前支持的协议、客户端官方说明、操作系统版本和套餐设备限制。“支持 Windows、Mac、Android、iOS”只是一句概括，不能证明每个系统版本、每个客户端和每种设备都能直接使用。功能和应用分发方式可能变化，购买前应查看当时的官方说明。

## 先列出自己的设备清单

写下需要用的电脑、手机、平板、系统版本、家用网络和移动网络场景。确认是否需要同时在线，而不只是“安装几台”。有些套餐限制可登录设备数，有些按并发连接数计算，还有些限制账号共享；这些口径不能混为一谈。询问是否可在账号后台注销旧设备，以及更换手机后如何重新绑定。

如果你有较旧系统或不常见设备，先查看客户端官方支持的最低版本和最近维护状态。不要只凭应用商店中的评论或搜索页面判断兼容性；确认开发者名称、发布来源和更新日期。服务商的配置说明也应标明适用客户端与版本，而不是只给一个没有说明的通用文件。

## 对照三份资料

第一份是服务商的套餐与帮助文档：确认支持协议、推荐客户端、账户限制和更新方式。第二份是客户端官方发布说明：核对系统版本、导入方式、权限与近期维护状态。第三份是设备操作系统的安全与安装说明：通过正式应用商店或项目发布渠道获取软件。三者若有冲突，应向服务商询问并保存答复。

服务商页面若推荐一个客户端，不表示该应用由服务商开发或由其负责更新。分别确认应用的实际发布者、项目主页和下载来源。避免从来历不明的网盘、群文件或仿冒页面安装程序；如果找不到官方发布渠道，应暂停安装并确认来源。

## 兼容矩阵如何记录

| 设备 | 需要核对 | 证据来源 |
| --- | --- | --- |
| Windows 电脑 | 系统版本、客户端发布者、导入方式、更新日期 | 客户端官方文档与服务商说明 |
| macOS 电脑 | 芯片架构、系统版本、权限要求、升级路径 | 应用发布页与系统开发者说明 |
| Android 设备 | 最低系统版本、安装渠道、后台运行限制 | 应用发布者与系统官方帮助 |
| iPhone / iPad | 商店地区、应用要求、订阅和配置说明 | App Store 发布者信息与服务商文档 |
| 多设备 | 可登录数量、并发限制、换机解绑规则 | 当前套餐条款与账户后台 |

表格是购买前的核对框架，不代表某个特定客户端支持所有系统。把核验日期和客户端版本写在每一格；如果某版本没有公开资料，就标“未确认”。不要把过时的安装教程当作当前兼容承诺。

## 配置文件和订阅地址也要保护

服务商发来的订阅地址或配置文件可能包含账户令牌。只在可信、官方文档明确的客户端中操作，不要上传到公开转换服务、粘贴到不可信网页或在截图中暴露完整链接。遇到客服问题时，先提供错误时间、设备系统和客户端版本；确有必要提交截图时遮掉地址、令牌和账号信息。

客户端更新后，配置格式或导入行为可能变化。遇到问题先查看应用发布说明、服务商帮助中心和错误提示，确认是否为客户端或套餐支持问题。不要为了让旧配置继续运行而从不明来源下载脚本或关闭设备安全设置。

## 购买前的兼容性确认

在付款前，把需要支持的所有设备发送给商家，询问对应套餐是否包含这些系统、设备数按什么方式统计、是否有额外客户端费用和配置更新支持。保存页面或工单答复。若你依赖某台重要设备，先确认可退款或试用条件，再考虑长期套餐。

兼容性是“当前套餐 + 当前客户端 + 当前系统版本”的组合结果，不是品牌永久属性。系统或应用更新后应重新查阅资料。任何兼容结论都应注明来源与日期，不能把一台设备成功导入配置说成所有用户和所有设备都会成功。

## 为每台设备建立简单清单

可以记录设备型号、操作系统版本、客户端名称与版本、安装来源、最近更新日期和账户是否仍在使用。清单不应包含密码、完整订阅地址或令牌。更换手机、重装电脑或转让设备前，先在服务商账户中撤销旧设备会话，并按操作系统说明清除本机配置。家庭成员共用套餐时，确认服务商的设备数量和同时连接限制，并为每个人使用独立的系统账户，避免把个人凭证复制到多人设备。出现兼容问题时，这些记录也有助于区分系统更新、客户端变化和套餐限制。
